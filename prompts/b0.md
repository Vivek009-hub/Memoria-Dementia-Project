## 1. CURRENT OBJECTIVE

Build the initial backend infrastructure for Memora.

The final architecture should be:

```text
Client
   ↓
Express API
   ↓
Application Layer
   ↓
MongoDB / Mongoose
```

At the end of this task, the backend must be able to:

1. Start successfully.
2. Connect to MongoDB.
3. Expose `/api/v1/health`.
4. Return a standardized health response.
5. Handle errors centrally.
6. Log requests.
7. Pass automated tests.
8. Pass linting.
9. Follow the documented project architecture.

# 10. SERVER ENTRY POINT

Create:

```text

```

3. Start the HTTP server.

# 12. HEALTH ENDPOINT

Implement:

```http
GET /api/v1/health
```

Return HTTP 200 with:

```json
{
  "success": true,
  "service": "memora-api",
  "status": "healthy"
}
```

The endpoint should not expose secrets or internal infrastructure details.

---

# 13. API RESPONSE FORMAT

Follow the architecture specification.

Success:

```json
{
  "success": true,
  "data": {}
}
```

Errors:

```json
{
  "success": false,
  "error": {
    "code": "RESOURCE_NOT_FOUND",
    "message": "Resource not found"
  }
}
```

The health endpoint may use the exact health response defined above.

---

# 14. ERROR HANDLING

Create centralized error handling:

```text
server/src/middleware/error.middleware.js
```

Also create:

```text
server/src/middleware/notFound.middleware.js
```

Expected flow:

```text
Request
   ↓
Route
   ↓
Controller/Handler
   ↓
Error
   ↓
Central Error Middleware
   ↓
JSON Response
```

Do not expose stack traces in production responses.
